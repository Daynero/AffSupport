# Unattended agent handoff contract

Runner remains model-independent. A separate supervised local agent bridge is a required configured capability for unattended repair handling. It may adapt an existing agent execution service; no particular model product integration is assumed available. Implement a process adapter that starts a preconfigured bridge executable by fixed argv, not an executable or shell string supplied by release intent. Installation registers bridge identity/protocol version and allowed scope; preflight checks it without a model call.

Durable messages: submit(jobId, fingerprint, runId, redactedDiagnosticRef, allowedRepairScope), query(jobId), acknowledge(jobId), result(jobId, status, repairReference). jobId is stable from run/failure fingerprint. Bridge persists acceptance before acknowledging; duplicate submit returns same job and never starts a second repair. Delivery is at-least-once with durable deduplication, not an unsupported exactly-once network guarantee.

Worker sends only after deterministic retries are exhausted. The bridge starts one repair job and can operate without a live chat. No credentials are put in prompt/diagnostics; any required tool access follows preconfigured scope. Results: repaired(reference), cannotRepair(reason), needsExternalDecision(reason). An accepted or repaired response never marks release gates passed: worker revalidates evidence and reruns affected gates. Source repair requires a new linked frozen intent as already defined; published versions cannot be replaced.

Bridge transport failure: persist delivery_pending and retry with backoff (30 s to 5 min) without model calls. Unlike a failed release operation, delivery retries may continue while the release remains blocked, unless the explicit overall deadline expires or run is cancelled. Reconnect queries jobId before resubmission. Bridge permanent failure or needsExternalDecision is exposed in status; do not claim autonomous completion when genuinely blocked. No owner action is required merely to recover a temporary bridge outage.

Test a fake bridge implementing persistent dedupe plus an actual configured bridge contract smoke: terminal closed; failure delivered; job accepted; response lost; bridge restarted; same job recovered; repair reference returned; release gate rerun. Normal release and bridge health checks cause zero model invocations. A protocol seam without a configured functioning consumer is not a completed handoff feature.
