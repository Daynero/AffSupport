# Contract: candidate execution isolation

## Selected boundary

На macOS release host використовується **окрема непривілейована OS verification identity**, створена trusted installer/enrollment, не користувач власника checkout. Candidate builds, test code та Playwright/native beta journey не запускаються з його UID. OS permissions/ACL забороняють verifier identity читати host checkout, release owner's HOME/Keychain/SSH/cloud credentials/config keys і trusted admission/target store. Private verifier HOME й per-run scratch; джерело передається exported tracked snapshot без `.git`, ignored files і secret dirs. Existing worktree provisioning не переносить keys у sandbox. Runtime package copies і beta fixtures мають окремий дозволений scratch; archive originals read-only.

Сам worktree, `env={}` чи приватний HOME під тим самим UID не достатні. Якщо host не має налаштованої identity/ACL/process launcher, preflight повертає `EXECUTOR_ISOLATION_UNPROVEN`; no same-user fallback, no automatic elevation. Налаштування host — одноразова окрема prerequisite, без придбання VM/service. Disposable Docker PostgreSQL/edge runtime використовує лише isolated verification network/volumes; Docker socket не передається кандидату.

Trusted launcher та verifier працюють поза sandbox. Build inputs — allowlisted source/dependency/toolchain snapshots; writable outputs — scratch. Після build trusted importer читає файли через safe descriptors, відхиляє symlinks/device/hardlink escapes, звіряє original tracked source snapshot і canonical artifact manifest, копіює у власний 0700 content-addressed store та повторно хешує. Кандидат не має права писати admission, policy, evidence або target receipts. Environment містить лише versioned public build inputs та scoped beta control credentials, ніколи production write credentials.

## Network and browser

Network boundary enforcement — enrolled macOS PF rules для dedicated verifier UID, default-deny egress для всіх його processes/children, IPv4/IPv6 TCP/UDP включно з direct DNS/QUIC. Єдиний дозволений destination — fixed trusted loopback proxy socket; прямі localhost agent/DB/backend/management connections теж denied. Global skip/rule precedence, alternate interface, non-PF exception або непідтверджений effective ruleset → preflight blocked. Installer налаштовує це як окрему authorized host prerequisite, не вимикає чинний firewall чи захист і не робить automatic elevation під час mini. Executor proof pin UID, effective kernel ruleset digest, proxy configuration/digest та canary self-test result; admission звіряє їх fresh перед candidate execution.

Build/static/unit execution network-denied після підготовки frozen dependencies: навіть proxy не відкриває egress для цієї phase; install scripts не отримують host secrets або write network. Native/browser journey допускає тільки bound loopback beta/agent та explicit backend/auth origins через trusted allowlisted proxy. Trusted proxy перевіряє destination і HTTP endpoint/method/synthetic control scope; unrestricted CONNECT tunnel заборонений. Для HTTPS використовується scoped inspection із per-run CA, довіреним лише приватному verifier browser/user context, без зміни owner/system trust store; upstream TLS перевіряється штатно. Непідтримуваний opaque/pinned transport блокує потрібний check. Proxy не логує auth/body content; не передає server write credentials і забороняє arbitrary provider management/deployment paths. Config/destination drift блокує admission. Важкі children проходять existing execute/resource admission, NICE і bounded output/deadlines.

Exact production candidate preview: trusted Playwright context із canonical page URL, static manifest-only `route.fulfill`, fixed checked headers/MIME, no service worker/cache. Auth/backend/local-agent traffic реальний, без fixture responses, через scoped proxy. Candidate cannot alter host route handler. Відсутня можливість real auth/control в дозволеному scope → blocked; postactivation live browse не використовує broker і окремо доводить actual CDN serving.

## Required hostile acceptance

Candidate script пробує прочитати production secret canary за відомим абсолютним шляхом у original checkout та HOME, через symlink, child process і inherited fd; доступ має бути denied. Спроби записати trusted admission/baseline/artifact, використати Docker/SSH socket, parent checkout та management API також denied. Parent canaries/store лишаються незмінними. Тести перевіряють фактичну OS відмову, а не відсутність env key. Negative control може читати лише дозволений scratch/public fixture. Runtime tests з native package виконуються саме під isolated identity; запуск під owner UID не приймається як proof.

Network-negative tests знімають HTTP_PROXY/HTTPS_PROXY і пробують direct TCP/UDP/DNS/QUIC, IPv4/IPv6, native child process та пряму loopback management/agent connection. Kernel має deny всі маршрути поза proxy незалежно від env або client library. Спроба CONNECT до management service чи path/method поза bound scope через proxy відхиляється. Positive control проходить тільки дозволений beta/control endpoint. Змінені PF/proxy rules, UID або canary result анулюють executor evidence; відсутність kernel enforcement не компенсується application proxy boolean.
