# Quickstart: перевірка відновлення зв'язку

Машина виконує одну важку річ за раз: `uptime` перед кожним прогоном; vitest — `--pool=forks --poolOptions.forks.singleFork=true`. Результати записуються в [findings.md](./findings.md).

## 0. Автоматичні перевірки

```bash
uptime
npx vitest run --pool=forks --poolOptions.forks.singleFork=true \
  tests/link-owner.test.tsx tests/stream-client-token.test.ts tests/stream-watchdog.test.ts \
  tests/link-availability.test.tsx tests/reconnect-surfaces.test.tsx tests/agent-shutdown-streams.test.ts \
  tests/agent-auth-limiter.test.ts tests/pair-handshake-origin.test.ts tests/link-analytics.test.ts \
  tests/analytics-connection-command.test.ts
npm run verify
```

## 1. Реальні середовища (ручні; кожен рядок → findings.md з датою, білдом, результатом)

### 1.1 Safari 18, hosted-сайт (Q1)

1. Відкрити https-сайт у Safari з запущеним агентом. Очікування: стан «браузер блокує з'єднання», провідна дія «Відкрити в Soty», другорядна «Завантажити».
2. Консоль: записати точний текст помилки (mixed content / access control). Якщо fetch пройшов — зафіксувати версію Safari; R8 нешкідливе.
3. Натиснути «Відкрити в Soty» на сторінці інструмента з query → локальна копія відкрилась на тій самій сторінці.

### 1.2 Safari 18, локальна копія (US1, US2, US4)

| # | Крок | Очікування | Межа |
| --- | --- | --- | --- |
| a | Транскрибація, вставити текст у транскрипт, не зберігати; вийти з агента з трею | «зв'язок втрачено» через 3–10 с; текст на місці | FR-002 |
| b | Запустити агент (токен незмінний) | «підключено» ≤ 5 с; стан транскрибації перечитаний; живий прогрес іде | FR-005 |
| c | Видалити `session-token.json` в App Support, перезапустити агент | in-page спарювання ≤ 5 с без переходу; живі події працюють | FR-006, FR-017 |
| d | Закрити кришку 2 хв, відкрити | ≤ 10 с після пробудження — або «підключено», або перевірка; ніяких зависань | FR-003/004 |
| e | Простір → зупинити агент → чип «Soty не підключено» → «Перепідключити» при зупиненому агенті | індикація спроби, результат «не запущено», дія «Відкрити Soty» | US2.1 |
| f | «Акаунт» після b | «Під'єднати» видима при розриві, не показує стару версію як поточну | US2.2 |
| g | Відкрити 8 вкладок локальної копії, дивитись на останню | живі події йдуть саме в ній | US4.4 |
| h | Відкрити копію через `http://localhost:43120` | POST-дії працюють | US4.3 |

### 1.3 Chrome, hosted-сайт

Повторити 1.2 a–f. Додатково: вимкнути Wi-Fi на 1 хв (loopback живий) → інструменти працюють, онлайн-перевірка відкладена (US3.4).

### 1.4 Агент (macOS + Windows)

| # | Крок | Очікування |
| --- | --- | --- |
| a | Дві вкладки з потоком; `kill -TERM <agent>` | процес вийшов ≤ 5 с (Q2); обидві вкладки повідомили розрив ≤ 10 с |
| b | Дві вкладки; запит оновлення через лаунчер / `AGENT_INSTALLED_RELEASE_PATH` | драйн → вихід 76 ≤ 5 с після завершення роботи; лаунчер перезапустив |
| c | Вкладка зі старим токеном (змінити `localStorage.agentToken`), 25 запитів/хв; нова вкладка з чинним | нова не отримує 429 |
| d | 9 вкладок одного каналу | витіснена вкладка чекає 5–30 с, не цикл |

### 1.5 Повідомлення (US3)

| Причина | Як відтворити | Поверхні, де перевірити текст |
| --- | --- | --- |
| не запущено | вийти з агента | шапка, головна, транскрибація, стітчер, простір (чип, меню дій, діалог обробки, прев'ю), «Акаунт» |
| застарілий для інструмента | бета-агент зі штучно зниженим `toolContracts.stitcher` | ті самі |
| health без `apiVersion` | `python3 -m http.server 43120` із відповіддю `{}` | шапка/головна: «не вдалося підключитися» |
| entitlement недоступний у пільзі | бета: вимкнути `issue-agent-token` | інструменти працюють; банер «перевірка акаунта відкладена» |

## 2. Діагностика (US6; бета зі стеком і реальним ingest)

1. Виконати 1.2 a–c, e та 1.4 a на беті.
2. `npm run analytics -- connection --period today --json` → є `losses`, `recoveries`, `recovery_mode.manual ≥ 1`, `failed_checks_by_reason.not_running ≥ 1`.
3. `npm run analytics -- journey <beta-email> --json` → послідовність `link_lost` → `reconnect_clicked` → `link_check_started` → `link_check_completed` → `link_recovered`; жодного токена/URL у properties.
4. Переконатися, що жодна з нових подій не відкинута guard-ом: у консолі браузера немає `analytics event rejected`; у `supabase/tests/database` є тест на кожен новий ключ.
