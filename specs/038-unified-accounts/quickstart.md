# Validation guide: 038

Implementation acceptance guide. Actual results and their limits are recorded below and in [independent reviews](reviews/fix-log.md).

## Environment

Use isolated beta/local Supabase, two editor sessions, a viewer and a nonmember. No production writes or migration pushes. Follow [BETA.md](../../docs/BETA.md). Keep `.specify/feature.json` on the active parallel feature; use explicit 038 context with read-only/no-persist path resolution.

At implementation start run `npm run beta:doctor`; use `npm run beta:up` only after prerequisites/isolation checks pass. Run heavyweight checks serially. Builds/release remain separate from this planning task.

## Fixture

Seed a dedicated test team with 50 socials, 500 RK, up to five manual/linked launches each, long names, labels/markers and at least one empty social. Smaller deterministic finance fixture: five RK under one social; a second social for transfers. Include balance-only, topup-only, spend-only, explicit zero, cleared-null, yesterday-only, no-data and backdated-before-creation cases. Add parent/child independent archives and repeated restore gaps. Never use real 2FA/financial content in fixtures or recordings.

Use explicit pinned test date/time and two zones including a DST boundary. Isolated PGlite fixture: `tests/support/team-unified-accounts.ts`. PostgreSQL assertions: `supabase/tests/database/unified-accounts.test.sql`.

The browser load fixture is created by `node scripts/seed-accounts-fixture.mjs`. It only connects to local beta, creates a separate team, never resets another team's work, and verifies owner/count/hash before reuse. Current fixture: team `92754a0b-facc-4b54-8d78-95c055ad24a0`, 50 socials / 500 РК / 2500 manual runs; SHA256 `f78eb6de276bf4cc431fd2176e7c610d150baf2aaa9cf2d2b385fbcf0126a340`. Metadata: `scratchpad/038/accounts-load-fixture.json`.

## Browser quality / performance (SC-004/006)

Record OS, browser/version, CPU, display refresh rate, viewport, build SHA and fixture hash. Use release-mode web build and Chromium on a 60 Hz profile with no CPU throttling; run three 10-second drags after warm-up (RK within group, social compacted, edge autoscroll). Measure frame intervals from capture to drop excluding initial load; steady-state p95 ≤20 ms and no interval >50 ms, capture feedback within 50 ms after 500 ms hold. Record raw timing trace and video path. A failure is not waived by an average FPS; optimize and rerun affected scenario. Repeat gesture correctness in supported Safari/WebKit and Windows Chromium; real touch device verifies scroll-before-hold, no page freeze and no competing gesture.

Check 390/768/1440 px plus existing layout breakpoints, 200% zoom, light/dark, reduced motion and keyboard-only. Table may scroll horizontally inside its own container, but controls/headers/drop target/focus remain reachable and page must not overflow. Existing equal-row-height assertions may need replacing with content-fit assertions because multiple launches have variable height; do not delete checks without replacement. Verify text contrast ≥4.5:1 for all seven data-palette colors.
