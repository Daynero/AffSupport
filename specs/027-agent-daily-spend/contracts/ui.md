# UI contract: Акаунти → фінанси

## Одна дата, один контекст

Фінансовий режим в Акаунтах має один state owner: mode(day/month), selectedDate/month, timezone, focusedAgent, drafts, snapshot. Звичайні запуски/теги/завдання залишаються доступними; нова фінансова панель не дублює недатовані Money fields. У фінансовому режимі групування історичне за selected period; звичайний список Акаунтів показує поточний соц. Назва періоду й контекст групування видимі.

Toolbar: попередній період, дата/місяць із календарем, наступний період; Сьогодні / Цей місяць / Минулий місяць; «Фінансова виписка простору». Calendar/DateField/SegmentedControl/IconButton беруться з чинного inventory. Не створювати новий календар або нову систему модалок.

Beta review: використовується `TaskDateFilterControl` з inventory RangeCalendar, без all-time/clear для фінансів. Завершений довільний проміжок до 366 включних днів переходить у звіт; один день — у введення. Стрілки зсувають довільний проміжок на його тривалість, повний місяць — на місяць. Dirty guard зберігає обидві межі; drill-down і повернення відновлюють вихідний проміжок.

| Режим          | Рядок агента                                             | Підсумок                                             |
| -------------- | -------------------------------------------------------- | ---------------------------------------------------- |
| День           | ID, Залишок, Поповнено, Спенд, історія, меню перенесення | spend і topup за день, кількість внесених значень    |
| Місяць         | ID, сума Поповнено, сума Спенд, відкриття денних деталей | окремі spend/topup за соц і простір                  |
| Історія агента | записи/виправлення/перенесення та legacy block           | суми за вибраний період, без додавання old revisions |

Денні залишки доступні через календар і історію. Не показувати «залишок за місяць» або обчислений balance без окремої вимоги. Немає даних, внесений нуль, loading і failed read — чотири різні стани.

## Введення

Поле має ключ team/agent/date/metric. Значення snapshot не перезаписує dirty draft. Enter save; Escape revert; Tab зберігає валідний draft і рухає focus. Стан saving/saved/error/conflict прив'язаний до цього ключа. При invalid Tab фокус лишається в полі з поясненням; network error не забирає введення.

Зміна дня, режиму, простору або закриття dirty editor викликає один ConfirmDialog: зберегти / відкинути / залишитися. Save завершує всі pending edits і лише потім navigation; помилка лишає контекст на місці. Якщо запит уже відправлений, не пропонувати скасування, яке удає rollback: дочекатися результату або перевірити receipt при відновленні зв'язку.

«Сьогодні» — динамічний режим. Північ із чистим editor оновлює дату; dirty/pending зберігає попередню date і показує перехід до нового дня після вирішення. Історична дата фіксована. Foreground/online повторно перевіряє дату й snapshot, без recurring network polling.

## Місячний огляд, копіювання, очищення

Місячний огляд відкриває денний запис з того самого агента; Back повертає місяць, фокус, пошук і scroll. Фільтр списку не приховує область загальних totals/export: вони підписані «Весь простір». Copy із назвами/ID працює тільки у денному режимі з фактично внесеними поповненнями та історичним соцом; включає дату/USD. Існуючі ±50 можна зберегти як спосіб змінити денний підсумок, а не створити платіж; чинна семантика snap має явні unit tests і ніколи не змінює інші дні.

Одиночне очищення залишку, поповнення або спенду показує Undo, прив'язаний до server undoReference. При новішій зміні поля Undo показує конфлікт, не відновлюючи старе поверх нового; повторне натискання не додає зміну. No-op clear не показує Undo.

Clear: підтвердження показує дату, показник і кількість; Undo повертає лише власне одиночне або масове очищення, не перезаписує новіші зміни. Журнал доступний після clear. Немає автоматичного clear після copy, export або зміни дня.

У місячному огляді й Excel повернення X → Y → X дає одну колонку/рядок агента під X та одну під Y. Групування спирається на UUID, а не однакові текстові назви.

## Перенесення та legacy

Форма створення агента передає IANA timezone пристрою через useAccounts.addAccountAgent; початкова дата повертається з серверного розміщення. Перевірити створення поблизу півночі та читання з іншого timezone.

MoveAgentDialog: вихідний соц, ціль із пошуком у цьому просторі, дата, пояснення історичної належності. Недопустиму дату пояснювати останнім записом; якщо сьогодні вже є фінанси, показати доступність перенесення наступного дня. Нове розміщення не переносить учорашні значення в сьогоднішні поля. Успіх інвалідує фінанси, accounts і task agent labels.

LegacyFinanceReview: оригінальні недатовані поля й попередження, що «Додати» було запитом; окремо підтвердити дату, валюту та фактичну суму кожного показника. Не вибирати дату або позначку «оплачено» автоматично. Уже імпортований показник має посилання на створений запис.

## Доступність та перевірка layout

Read-only member бачить суми/історію/export без write controls. Стан має текст/іконку, не лише колір. Focus повертається до trigger після drawer/dialog; accessible label включає агента, дату й показник. На вузьких екранах три поля стають рядками всередині агента, а month matrix прокручується у власній області. Перевірити light/dark, 320–1600px та обидві сторони всіх чинних breakpoints; не скорочувати повний ID у файлі або доступному підписі.
