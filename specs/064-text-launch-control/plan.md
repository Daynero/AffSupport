# План 064 · Помічник запусків і чарунки

**Гілка** `064-text-launch-control` · **База** `origin/beta` `55154405` · [Вимоги](spec.md) · [Задачі](tasks.md) · [Дослідження](research.md)

## Що постачаємо

У вкладці «Запуски» простору пілоту з'являється поле помічника. Репліка коштує 1–2 чарунки, ціна видна на кнопці. Вона створює чи змінює звичайні чернетки, які одразу видно в списку. Запуск відбувається кнопкою на картці перегляду, без Claude. Будь-яку команду можна скасувати. Переклад 063 платиться тими самими чарунками з ціною на кнопці «Перекласти». У хедері видно баланс, в адмінці — AI-бюджет місяця.

## Технічний контекст

TypeScript strict, ESM, React + HeroUI v3 у вебі (лише компоненти з `components/ui` і токени з `styles/tokens.css`), Supabase Edge для `assistant` і `transcript-translate`, PostgreSQL для стану й обліку. Локальний агент не змінюється: запуск іде наявним шляхом 053 → виконавець. Модель за замовчуванням — Haiku 5.5, остаточно після бенчмарку. Тести: Vitest single-worker, pgTAP, браузер на локальній beta з підміною провайдера.

## Послідовність

1. **Основа** (T001–T008): реєстр полів, злиття дефолтів, ціни, облік чарунок з переходом 063, міграції помічника, клієнт Claude.
2. **MVP — історія 1** (T009–T013): репліка → чернетки в списку → форма. На підміні провайдера, у пілоті Goor.
3. **Історії 2, 3, 5** (T014–T020): уточнення й правки, перегляд і запуск кнопкою, скасування. Після цього помічник корисний щодня.
4. **Історія 7 + хедер** (T021–T023): ціна на кнопках, CreditsButton, переклад на чарунках.
5. **Історії 4 і 6** (T024–T027): кілька РК і винятки, дефолт офера й ланцюжки.
6. **Історії 8 і 9** (T028–T030): адмінка, матриця безпеки, бенчмарк із реальним провайдером.
7. **Приймання** (T031–T035): діагностика, локальна beta, next, продуктовий замір.

Реальний провайдер вмикається лише після T029 (матриця безпеки) і T030 (бенчмарк). До того всі тести йдуть на підміні.

## Викат

- Міграції адитивні. Нові номери брати на інтеграційній базі як наступні унікальні позначки часу.
- Шлях: beta → next через повний раннер, бо змінюються Edge-функції й БД (не лише веб). Прод — лише через promote за словом власника.
- Перемикання 063 на чарунки — прапорцем `translation_billing` на початку київської доби після деплою.
- Пілот: спершу Goor, далі простори за списком в адмінці.
- Окремий workspace у Claude Console зі spend limit $100 налаштовує власник. Soty показує нагадування в адмінці.

## Перевірка конституції

| Принцип | Як дотримано |
| --- | --- |
| I. Типізовані межі | Вхід браузера, вихід моделі й рядки БД приходять як `unknown` і проходять перевірку. Structured output за JSON Schema з реєстру й повна серверна валідація плану. Тест відхилення зайвих полів |
| II. Єдине джерело контракту | Реєстр полів і ціни в shared. Веб і Edge беруть з одного dist, shared перебудовується перед споживанням |
| III. Найменші права | RLS на кожній таблиці, `revoke all`, вузькі grants, `security definer` з порожнім `search_path`, адмінські RPC через `is_admin()`. Перевірка прямого виклику поза UI |
| IV. Ресурси агента | Агент не змінюється, запуск іде наявним виконавцем 053 |
| V. API та помилки | Стабільні коди причин ([команди](contracts/commands.md)). UI не розбирає текст помилок провайдера |
| VI. Інтерфейс і стан | Компоненти HeroUI з інвентарю й токени. Клавіатура й фокус. Баланс оновлюється на київській півночі й при поверненні у вкладку, без polling |

Винятків із конституції немає.
