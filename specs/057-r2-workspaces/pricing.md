## Межі зберігання та роботи

Логічні GB = поточні originals + збережені користувацькі результати + залишені версії + кошик. Внутрішні прев'ю, технічні публікаційні копії й резерв — витрати Soty, не подвійна квота. Незалежна user copy створює нову логічну charge; кілька посилань на ту саму canonical version — одну.

Максимум файла — менша з 100 GB, доступної після reservations місткості й вузької межі конкретного tool. Solo не може завантажити100GB у10GB квоту. Кошик30діб; default поточна +попередня версія на7діб у межах квоти, далі явне keep. Backup після logical purge лишається30–31добу; references активних каталогів/завдань не видаляються мовчки.

Rolling30d user ingestion ≤3× місткості, automatic derivatives ≤1×; initial migration окремо. Технічний retry одного generation не рахується повторно. Delivery envelope до10×GB/30d і5M authorized requests/TB/30d (мінімум500k/організацію), fair-use review понад нього, без автоматичного overage. Захист, відкликання доступу й експорт не можна перервати spend cap. Кошторис включає request floor навіть для10GB Solo; workload caps доступні до покупки.

Неоплата платного плану:3доби grace → read-only/export, фонова генерація зупинена →90діб retention → попереджений purge →30–31доба backup. Старі Drive originals не видаляються. Старі grants зберігають проданий строк; credit за залишок розраховується з фактично сплаченої суми, невідома сума потребує явного адмінського погодження. Немає автоматичної платіжної інтеграції в scope цього релізу.

## Витрати: що підтверджено, а що треба виміряти

Provider rates повторно перевірено2026-11-14: [R2](https://developers.cloudflare.com/r2/pricing/), [B2](https://www.backblaze.com/cloud-storage/pricing), [Workers](https://developers.cloudflare.com/workers/platform/pricing/). Вихідна формула storage незмінна: `0.015*1.1U + 0.00695*1.4U = 0.02623U`, U — average logical GB, D=10% derivatives, V=30% додаткової backup history. Detailed geography/alternatives — [provider-research.md](provider-research.md).

R2 operations: `0.001125U + 0.36*max(0.5, 5U/1000)` —250k writes/TB,5M reads/TB, мінімум500k reads/org. Ця модель навмисно рахує floor при невеликому storage. Normal download gateway — authenticated Cloudflare Worker, independent Node gateway лише в DR; тарифи Workers request/CPU та DB authorization входять у non-byte allowance і перевіряються навантаженням. Independent host transfer/preview/metadata network не стає безкоштовним через R2: quoted фактичну суму підставляємо замість припущень.

Compute/transfer reserve лишається$5/TB. **Нова ціль операційної ефективності**, а не виміряний факт: `F = $0.50/організацію + $0.20/оплачену людину + $0.10/простір` на місяць для auth/API/routine support-variable. Для Solo це$0.80 замість попереднього припущення$3. Це можливо лише за автоматизованого provision/diagnostics і низької середньої ручної роботи. Зарплати, розробка, тривала персональна підтримка, CAC, податки та fixed infrastructure не заховані в цій цілі; вони окремі. Старе$3 не «спростовано»: нижче збережено stress case. Ручний grant за$5 має рахувати фактичні хвилини обробки; якщо вони не вкладаються, margin gate не пройдено.

## Шість клієнтів по $5 проти одного за $30

Порівнюємо однакові сумарні ресурси:60GB,6людей,6просторів,3M reads/місяць при повному storage. «Один за$30» — контрольний сценарій однієї billing-організації, не новий SKU і не підміна одного Solo за$30.

| ---------------- | ------: | -------------: | ------------------------: |
| 6 × Solo$5       |  $30.00 |         $11.84 |                    $18.16 |

Шість дешевих клієнтів дають на$4.38 більше змінних витрат: п'ять додаткових org overhead і п'ять додаткових fixed payment fees. Це не заважає стратегії доступності: нижчий поріг може привести більше покупців, розширення й рекомендації. Але **6×$5 не автоматично прибутковіше за1×$30** при однаковому навантаженні. Для такої самої contribution в цій моделі потрібно8 Solo, або виміряна перевага acquisition/retention/expansion. Вартість залучення рахуємо для всієї когорти, а не порівнюємо CAC одного$5 покупця з CAC одного$30 покупця.

При Solo contribution$3.03/місяць тримісячний payback дає optimistic CAC ceiling$9.08 **до fixed allocation і churn**; фактичний допустимий CAC нижчий. До дорогого paid acquisition потрібні виміряні activation→paid conversion, support minutes,30/90d retention, add-on conversion та refund. Не вигадувати ці показники з56 зареєстрованих користувачів. Перші дешеві пакети — доступний продукт із контрольованим бюджетом, не доведений marketing arbitrage.

## Стреси та одноразова міграція

- Ретеншн при daily full rewrite значно дорожчий: provider research оцінює $232.65/TB-month тільки storage. Це поза included ingestion envelope; без лімітів тарифи небезпечні.
- Worst admitted churn 3×quota newly committed за30д +1×quota automatic derivatives може створити до4×quota extra retired backup (вікно 31д може захопити частину сусіднього періоду; rolling ліміт, не calendar reset). Capacity admission використовує також поточний physical-history budget ≤5×quota; вище зупиняє нові генерації до quote/reclaim, зберігаючи раніше прийняті retention commitments. Нормативна маржа не гарантується для такого stress. Потрібен ledger фізичних байтів і stress drill, а не лише logical quota.
- 1 TB logical, 1.4 TB mature backup, 10 TB emergency downloads +1.4 TB restore: ~$72 B2 transfer за наявного 3× allowance; 10 TB logical → ~$720. Новий backup може не мати такого allowance: pessimistic до $114/TB logical за той самий трафік. Також worker/API/primary write та duplicate storage, quota reconciliation. 15% reserve — contribution buffer, не доказ достатності cash.
- Migration 1 TB: якщо старий Drive ще оплачується власником, Soty на overlap 7д потребує ~`26.23*7/30=$6.12` нового storage, плюс requests ~$2.93, compute reserve $5/TB і20% retry => ~$16.85 орієнтовного Soty overhead. 30д overlap => ~$40.99. Це окремий верхньорівневий provisioning budget, не додатковий рахунок користувачу і не точний інвойс; staging duplicates, complex natives, previews CPU й довгі маленькі файли можуть підняти суму. Кожен actual manifest дає власний quote.
- Copy ETA без throttling: 1 TB при100 Mbit/s ~22.2 год, при1 Gbit/s ~2.22 год; checksum/re-read, API limits, egress path та retries додають час. Глобальний паралелізм визначається провайдерним та фінансовим бюджетом, не кількістю браузерів.
- Розробка: rough planning 12–20 engineer-weeks +2–4 тижні pilot/DR qualification, висока невизначеність від Google Sheets/native й existing-data integrity. При внутрішній собівартості $2k–$4k/engineer-week це $24k–$80k до інфраструктури. Це сценарій бюджету, не строк/договір; T001 census звужує оцінку. Cutoff запускається тільки після готового релізу, не від початку розробки.

**Commercial go/no-go**: підставити measured object distribution/churn/preview CPU/requests, live invoice rates, paying org mix, retention й host quote; перевірити нормативну маржу SC-008 і грошовий stress reserve; лише потім затвердити ціни. Якщо факти не вкладаються, змінити запропоновані ціни/ліміти до продажу, а не обрізати вже проданий захист.

## Metadata and network budget qualification
