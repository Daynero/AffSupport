# Feature Specification: HEVC у каталогах без ручної конвертації

**Feature Branch**: `work/next-release-improvements`
**Created**: 2026-11-14
**Status**: Implemented; local native/focused/static qualification complete; combined release checks pending
**Input**: Створення каталогу з HEVC має працювати автоматично. Власник уточнив:
потрібні всі основні варіанти, зокрема камера/iPhone та завантажені ролики.

## User Scenarios & Testing

### User Story 1 — Створити каталог з HEVC (Priority: P1)

Користувач обирає HEVC-відео і створює каталог зі звичайною перезашивкою.
Застосунок сам готує сумісне відео, показує прогрес і завершує звичний процес.

**Why this priority**: сьогодні такий каталог зупиняється на відмові формату.
**Independent Test**: справжній HEVC проходить нативну обробку й дає перевірений
готовий файл; хеш оригіналу до/після однаковий.

**Acceptance Scenarios**:

1. SDR HEVC 8/10-bit, зі звуком і без нього, завершується сумісним відео.
2. HDR PQ і HLG отримують коректне SDR-відображення, без втраченої орієнтації,
   неправильної тривалості, розсинхронізації або залишених HDR-позначок.
3. Повернуті та зі змінною частотою кадрів джерела зберігають видиму орієнтацію,
   пропорції й тривалість. Непошкоджений підтримуваний HEVC не відмовляється лише
   через кодек, глибину кольору або частоту кадрів.
4. Сумісний H.264 проходить попереднім шляхом без додаткового перекодування.
5. Старий збережений висновок про непідтримуваний HEVC не блокує нову спробу.

### User Story 2 — Надійна спільна підготовка (Priority: P1)

Десять запусків/варіацій одного джерела користуються однією дороговартісною
підготовкою. Кожен має незалежну доставку і право скасування.

**Independent Test**: десять одночасних споживачів, скасування/видалення одного,
завершення решти, повтор після перезапуску й обмеження дискового кешу.

**Acceptance Scenarios**:

1. Одна версія джерела й політики має один активний конвертер.
2. Скасування одного споживача не зупиняє інших і не видаляє їхні готові байти.
3. Останнє скасування чекає фактичного припинення роботи та прибирання.
4. Зникнення/зміна джерела або неповний запис не публікують частковий кеш.
5. Застарілий, змінений або неперевірений кеш не видається готовим; наступна
   спроба відновлюється без повторного використання часткового результату.

### Edge Cases

Пошкоджений/зашифрований потік, нестача диска, відсутній медіарушій, невідомі
метадані кольору, останнє скасування під час перевірки, зміна політики, старий
клієнт і відсутня діагностика. Для невідтворюваного джерела потрібна точна
відмова; результат з неправильними кольорами не називається успіхом.

## Requirements

- **FR-001**: Автоматична сумісність у створенні каталогу та споріднених нативних
  перезашивках; без ручного експорту, встановлення кодеків чи зміни оригіналу.
- **FR-002**: Охопити основні HEVC SDR, PQ/HLG, 8/10-bit, VFR, повороти,
  звук/відсутність звуку. Перевірити також сумісну базову частину камерного HDR.
- **FR-003**: Не змінювати чинний шлях сумісного H.264 і не застосовувати до
  конвертованого HEVC обіцянку незмінності пакетів оригінального тіла.
- **FR-004**: Результат перевіряється до доставки за відео, звуком, кольором,
  орієнтацією, тривалістю й цілісністю; помилка не стає успіхом.
- **FR-005**: Обмежені ресурси й кеш; ідентичність містить версію вмісту та
  політики. Немає часткового підвищення результату до готового.
- **FR-006**: Незалежні споживачі й припинення; фонові та пакетні шляхи мають
  ті самі гарантії. Одна невдала операція не псує решту черги.
- **FR-007**: macOS і Windows використовують спільну логіку та наявні засоби
  керування ресурсами. Старе негативне визначення придатності оновлюється.

### Analytics & Diagnostic Coverage

Стадії: отримання джерела → визначення сумісності → очікування/початок спільної
підготовки → конвертація → перевірка → готовий кеш → перезашивка → доставка.
Кожен споживач має свій ідентифікатор операції та спільний ідентифікатор
підготовки. Успіх, кеш, помилка, скасування, переривання, відновлення й відсутні
сигнали розрізняються. Нативний виробник → перевірка приватності → приймання →
збереження → CLI-діагностика перевіряються разом. Не збираються назви, шляхи,
URL, вміст, хеші користувацьких байтів або відповіді провайдера. Готова локальна
копія не доводить доставку каталогу або видимість результату користувачу.

### Key Entities

- Джерело і версія його вмісту; оригінал зберігається.
- Політика сумісності й перевірений підготовлений результат.
- Споживач підготовки з незалежним життєвим циклом.

## Success Criteria

- **SC-001**: Усі підтримувані випадки реальної медіаматриці завершуються
  відтворюваним сумісним файлом; хеш кожного оригіналу незмінний.
- **SC-002**: Тривалість відрізняється не більше ніж на два кадри або 100 мс;
  A/V розбіжність не перевищує 100 мс, пропорції й орієнтація збережені.
- **SC-003**: Десять споживачів одного джерела запускають одну підготовку;
  скасування одного не псує завершення інших.
- **SC-004**: Жоден частковий/пошкоджений результат не стає готовим кешем.
- **SC-005**: Для кожного контрольного збою відомі остання доведена стадія та
  причина або явно названа сліпа зона. Немає неправдивої доставки.

## Assumptions

«Всі варіанти» означає основні звичайні HEVC-файли камер і експорту, які
декодуються встановленим рушієм. Пошкоджені, зашифровані й несумісні спеціальні
багатовидові потоки не маскуються успішним неправильним результатом. HDR стає
SDR для сумісності каталогу; це явна зміна представлення, а не втрата оригіналу.
Публікація релізу лишається окремою авторизованою дією.
