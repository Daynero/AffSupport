## Dependencies and execution

T001–T006 restore the starting point. T007→T008 and T010→T011 define boundaries; T009/T012 are trust prerequisites. US2 T021–T025 may develop against mocked native boundaries after T007/T010, while US1 needs real barrier for install. US3 uses durable model from T010/T011, then supplies the recovery/diagnostic proof needed for US1 readiness. US4 depends on US1+US2+US3. No shipping increment enables capability with only a happy-path installer.

```text
setup → shared/manifest + native store/bridge + signing
      → US2 barrier/flush ─┐
      → US1 prepare/driver ├→ consented A→B + exact readiness
      → US3 recovery/CLI ─┘→ US4 legacy/A→B→C/release proofs → final verification
```

Parallel opportunities mean independent branches of work, not concurrent heavy local tests: US1 client tests T018 can be drafted alongside native driver tests T016 after contracts; US2 background tests T023 alongside native receipt tests T010 after shared schema; US3 CLI fixtures T029 alongside native fault-harness design T027 after receipt schema; US4 fallback tests T030 alongside release fixture design T031 after descriptor contract. Edits sharing shared types/Launcher/index/scripts remain sequential. No task carries a [P] marker while an incomplete prerequisite blocks it.

MVP is the complete safe macOS journey (US1+US2+US3 plus one-time US4 bootstrap), not US1 alone: explicit consent without workload preservation/recovery/diagnostics is not deployable. Incrementally land disabled contract/store/barrier changes with tests; enable native capability only after T012/T025/T029/T032. Extension hooks absent at generation; no hooks skipped by inferred condition.
