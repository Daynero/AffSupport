# Каталог ручних тест-кейсів

Статус усіх кейсів: **NOT RUN**. Це сценарії, не звіт про проходження.

Кожен рядок є окремим кейсом. Передумови групи додаються до передумов runbook; кожен кейс починається зі свого відновленого fixture, а не випадкового результату попереднього. «Підготувати стан» означає штатну адмінську дію або локальний тестовий fixture; за відсутності fixture — BLOCKED і задача на нього. Аналітичний CLI не змінює дані.

A = Safari owner, B = Safari editor, C = Chrome viewer; S = окремий Soty admin, X = зовнішня особа. За потреби S/X використовують додатковий ізольований профіль, не змінюючи основну трійку. Для ключових TEAM/ACL/LIFE/SYNC сценаріїв повторити з перестановкою Safari↔Chrome ролей. Доказ кожного кейсу: час, кандидат, до/після з дозволених сесій, фактичний terminal/відмова, correlation IDs, статус; форму див. execution-report.md. Для P0 зміни прав/тарифу обов’язкове підтвердження серверної відмови, не лише UI.

P0: блокер продажів при будь-якому FAIL/BLOCKED. P1: обов’язкова регресія кандидата; незастосовність доводиться scope. Тривалі операції не мають права лишатися невизначеними: записати очікуваний timeout/retry з контракту, а його відсутність — дефект.
