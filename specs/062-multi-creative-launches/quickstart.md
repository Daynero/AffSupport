# Quickstart: перевірка 062 на беті

Передумови: бета піднята (див. пам'ять про холодний старт), міграції 062 накатані через psql + `schema_migrations` (не `migration up`, не `db reset`). Простір для запису — тестова папка в Goor або фікстурний простір бети.

## 1. Кілька відео без перезашивки (US1, US2)

1. Запуски → новий → метод «Каталог».
2. Кинути 4 відео одним жестом → 4 рядки в полі креативу.
3. «Товарів у каталозі» = 100 → з'являється «Розподіл між креативами · 25 · 25 · 25 · 25».
4. Розгорнути, перший повзунок → 40: інші 20/20/20. Через поля: першому 40, другому 30 → 40/30/15/15; третьому 20 → 40/30/20/10.
5. Змінити 100 → 200: 80/60/40/20. «Порівну»: 50×4. Повернути 100 і 40/30/20/10.
6. Ввести «Товарів у каталозі» = 3 → лишається 4, попередження «Товарів не може бути менше, ніж креативів».
7. Перезавантажити сторінку — розподіл збережено.
8. Згенерувати. У каталозі: 4 блоки 40/30/20/10 у порядку, ID `<alias>-…`, у кожному блоці посилання лише на своє відео.

## 1a. Багато креативів (US2, FR-001)

Новий каталожний запуск, 100 товарів, кинути 120 зображень (фікстурна папка) → «Товарів у каталозі» стає 120, кожен по 1, список і розподіл прокручуються, підсумок скорочений.

## 2. Варіації (US3)

1. Запуск з §1, перезашивка увімкнена, варіації 30 при 25×4 → підказка `8 · 8 · 7 · 7`.
2. Варіації 3 → помилка «щонайменше 4».
3. Згенерувати (агент онлайн) → 4 набори, 30 файлів; різниця товарів між варіаціями одного відео ≤ 1.
4. Штучно зламати один набір → результат показує, який креатив; «Повторити» перезапускає лише його.

## 3. Зображення (US4, US5)

1. Новий каталожний запуск, 3 зображення JPEG/PNG ≥ 500 px, 90 товарів, R2 увімкнено, без розкладу.
2. Перемикача перезашивки, варіацій і тривалості немає; R2 і розклад є.
3. Спробувати кинути відео → відмова з поясненням, список без змін.
4. Згенерувати → 3 блоки по 30; H = `https://…/c1/<uuid>`, `curl -sI` без cookies → 200, `image/*`; Z/AA порожні; назви, описи й ціни — як у каталозі з білими (той самий генератор).
5. Лічильники загального пулу білих зросли так само, як для каталогу з білими на 90 товарів.
6. Той самий запуск з R2 вимкненим → H = посилання Drive, анонімне читання 200.
7. Запуск із розкладом на +10 хв → до часу H містить білі картинки пулу; після — посилання креативів; повторне анонімне читання перед записом пройдено.

## 4. Пакет і копіювання (US6)

1. Виділити запуск з 4 креативами, Cmd+C, Cmd+V ×3 → 3 чернетки з тими самими креативами й розподілом.
2. «Згенерувати вибрані» → 3 каталоги, кожен 40/30/20/10.
3. Картка показує `alias +3` і значок відео.

## 5. Менеджер каталогів і оновлювач (FR-021, FR-022, FR-024)

| Каталог | Видно з дій над вмістом | Не видно |
|---|---|---|
| одне відео | усе, як зараз | — |
| кілька відео | перезашивка (+ кількість варіацій), R2, унікалізація текстів | варіація посилань, оновлення картинок, ріст, заміна відео, перевірка посилань |
| зображення | R2, унікалізація текстів | решта, і кількість варіацій |

1. Відкрити менеджер для каталогів з §1, §3 і старого одиночного — набори дій за таблицею; список креативів у деталях.
2. Масовий редактор: увімкнути «ріст» для всіх → каталоги з §1/§3 пропущені з лічильником, інші змінені.
3. Каталог з §1: увімкнути перезашивку з 8 варіаціями → кожне відео перезашито в 2, блоки отримали свої варіації.
4. Каталог з §3: перемкнути R2 → H одразу переписані на Drive-посилання (і назад на `c1/`).
5. Запустити «Оновити зараз» двічі для каталогів з §1 і §3: блоки, префікси й тип збережені; H каталогу зображень не змінилися, тексти оновились.

## 6. Аналітика

`npm run analytics -- inspect launch <id>` (див. AGENTS.md) — `creativeKind`, `creativeCount`, стадії `creative_image.*`; для зламаного набору — `failedOrdinal` і код причини.

## 7. Регресія

Старий запуск з одним відео: відкрити, скопіювати, перегенерувати — працює; новий каталог має префікс, старий каталог при оновленні — без префікса.
