# Quickstart: перевірка на беті

Передумови: бета піднята (`colima start` → `beta:down` → `beta:up` після ребуту),
`uptime` load < 6, два акаунти (власник A, учасник B) на двох машинах або двох
профілях агента, підключений Drive з папкою `restitch-fixtures/` (30 зображень:
png/jpg/webp, 1 HEIC, 1 GIF, 1 SVG, 1 jpg > 50 МБ, 1 jpg з EXIF Orientation=6).

## US1 — пули без агента, нуль байтів на сервері

1. A вимикає агент, відкриває «Ре-стітч» у налаштуваннях простору.
2. «Додати папку» → `restitch-fixtures` у стартовий; «Додати файли» → 3 файли у фінальний.
3. Очікувано: лічильник стартового = 26 придатних, відсіяно 4 з причинами; «Зберегти» активна.
4. Зберегти. `SELECT count(*) FROM storage.objects WHERE bucket_id='team-restitch-images'`
   не змінився. Перезавантажити сторінку: ті самі джерела.

## US2 — учасник на чистій машині

1. B з чистим `TeamScreens/` і своєю бібліотекою компресора (запам'ятати кількість).
2. «Скачати перезшите» для відео. Очікувано: екрани з пулів A; у `Images/` B нічого не додалось;
   `TeamScreens/` має 2 файли `<materialId>-<md5>.<ext>`.
3. Повторити: у логах агента `[screen-cache] hit 2`, мережевих переносів картинок 0.
4. Замінити вміст одного файлу в Drive тією ж назвою, дочекатись синку, повторити:
   новий md5 у кеші, старий файл лишається до прибирання.
5. Фото з Orientation=6 у результаті стоїть прямо.

## US3 — фон і особисті

1. B вмикає особисті пули з іншою папкою. A вмикає оновлення каталогу з ре-стітчем.
2. Копії каталогу, зроблені вкладкою B: екрани з пулу A.
3. Інтерактивне скачування B: екрани з пулу B. Учасник C на успадкованих бачить
   пули A з назвами й кількостями без кнопок.
4. Учаснику D дати `process` без `download`: інтерактив → `RESTITCH_SOURCE_FORBIDDEN`;
   фонова задача D фейлить з цим кодом і її бере B.

## US4 — недоступність

По черзі з перевіркою панелі й скачування: перейменувати папку (без змін);
перемістити всередині простору (без змін); файл у кошик (`partial`, лічильник менше);
усі джерела слоту в кошик (`empty`, скачування каже «пул порожній», фонова задача
`RESTITCH_POOL_EMPTY` у чипі); відновити (знов `ready` без збереження);
переприв'язати простір до іншого кореня (`out_of_root`); повернути.

## US5 — перехід і межа

1. Простір зі старими uuid[]: після релізу банер «потребує перевибору», кількість = старих id.
2. Стара вкладка (попередній білд вебу) з новим пулом `drive`: claim → `RESTITCH_CLIENT_OUTDATED`.
3. Старий агент (попередній реліз) з новою вкладкою: `teamRestitchAgentTooOld`.
4. `curl` з токеном учасника на upload у бакет → 403 (INSERT-політики немає).
5. «Перенести старі картинки» → папка `Soty/Re-stitch images/start|end` у Drive, після синку
   джерело `available`, результат ідентичний.

## Гейти

- `npm run verify` не запускати на цій машині; vitest single-worker по файлах з
  contracts, потім `beta:verify` при load < 6.
- Інвентар бакета до/після: кількість об'єктів не зросла (SC-001).
