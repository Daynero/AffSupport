# Перезашивка: передача до наступного релізу

Стан на 2026-10-12: виправлення є в робочому дереві, на проді ще не перевірені.
Ця нотатка доповнює `docs/PRODUCTION.md`, не замінює його гейти.

## Що сталося і що виправлено

- У релізі `v1.2.6` HTTP route `/api/team/download` відкидав `process.screens`
  і `process.teamId`. Після переходу на картинки простору старі списки ids
  порожні, тому агент завершував перезашивку з `NO_SCREENS`.
  У поточному коді route вже зберігає ці поля; доданий HTTP regression test
  `tests/team-restitch-download-route.test.ts`.
- `RestitchDeliveryNotices` повторно оновлював toast при кожному render через
  нестабільний callback. Це запускало цикл оновлень і React error `#185`:
  чорний екран відтворено у Chrome на проді. Тепер кожна зміна стану
  повідомляється один раз; regression test використовує справжній ToastProvider.
- `ImageEmbeddingSection` перевіряв старі масиви зображень навіть коли слот
  показував Drive pool. Хибне попередження прибране для таких слотів;
  їхню доступність продовжує показувати сам pool.
- `teamRestitchSources` піднято з revision 1 до 2. Старий агент 1.2.6 більше
  не вважається здатним виконувати завантаження з Drive-картинками:
  веб показує вимогу оновити агент.

## Що обов'язково зробити для релізу

1. Включити у release SHA виправлену передачу screens у
   `apps/agent/src/team-bridge/routes.ts`, capability revision 2 і веб-фікси.
2. Випустити **новий агент та веб**, за канонічним runbook. Один веб-фікс
   не відновить перезашивку на встановленому агенті 1.2.6.
   Версію релізу ще не обрано; старі теги, assets та версію 1.2.6 не змінювати.
3. До релізу отримати зелені загальні перевірки й packaged-beta verification
   для exact release SHA. Поточні blocker-и `npm run verify`:
   - `format`: попередження для `tests/material-search-sql.test.ts`, далі timeout
     180 секунд;
   - `typecheck:tests`: неповна `STATUS_BY_CODE` у
     `supabase/functions/_shared/errors.ts` для `TeamErrorCode`
     (`SEATS_FULL`, `SEATS_IN_USE`, `SPACE_BLOCKED`, `TARIFF_BOUND` та ще двох
     кодів — точний список перевірити повторним typecheck).
     Ці blocker-и не виправлено в межах цього фіксу.

## Перевірка результату

- 88 цільових тестів пройшли; lint змінених файлів, форматування змінених
  файлів і build shared пройшли. Загальна перевірка не зелена;
  її загальний test phase не запускався через static failure.
- На packaged beta перевірити одне відео й кілька відео з папки: картинки з
  pools обох слотів доходять до агента, вихідний перезашитий файл збережений,
  сторінка лишається працездатною після успіху та відмови.
- Перевірити сумісність зі старим агентом: явна вимога оновлення,
  без запуску перезашивки з порожніми картинками.
- Після релізу повторити продовий сценарій, `investigate --as-of` і
  `audit --as-of`: немає нових `NO_SCREENS` та unknown-кодів для цього сценарію.
  Відсутній у проді 1.2.6 forwarded agent journal лишається сліпою зоною;
  її перевірка записана як T025 у `specs/031-platform-autoanalytics/tasks.md`.

Папковий пакетний сценарій і успішне збереження файла ще не перевірені на
оновленому packaged агенті або проді. Локальні тести не замінюють ці перевірки.
