# 064 · Контракт помічника запусків

Внутрішній API Soty між вебом і Edge-функцією `assistant`. Фізичні маршрути дотримуються формату Edge/RPC репозиторію. Особу, простір і права сервер бере з сесії. `teamId` у запиті лише вибирає область перевірки.

## Операції веб → Soty

| Операція | Вхід | Перевірка й результат | Claude |
| --- | --- | --- | --- |
| `conversation.open` | `teamId` | Право на запуски в просторі й увімкнений пілот. Повертає розмову (останні 50 повідомлень і картки), баланс, ціни | ні |
| `message.send` | `teamId`, `conversationId`, `text`, `contextCardId` (картка, яку бачить користувач), `clientKey`, `expectedPrice`, `priceVersion` | Межі (FR-034), ціна, баланс, місячний стоп → debit → розбір → виконання. Повертає повідомлення помічника з картками й новий баланс | 1 |
| `question.answer` | `questionId`, `optionId`, `clientKey` | Питання належить автору, відкрите й не застаріле. Застосовує вибір до тих самих кроків | ні |
| `review.show` | `teamId`, `selector` (`today` / `command:<id>` / `rows:[ids]`) | Будує картку перегляду (FR-014) | ні |
| `review.launch` | `reviewId`, `rows: [{id, version}]`, `clientKey` | Права, версії, готовність → приймання пакета 053. Якщо щось змінилося, `409 REVIEW_CHANGED` + нова картка | ні |
| `command.undo` | `commandId`, `clientKey` | Відкат ефектів команди (FR-017). Повертає «скасовано / лишилося з причиною» | ні |
| `command.status` | `commandId` або `batchId` | Стан кроків і рядків з доменних квитанцій | ні |
| `profile.confirm` | `proposalId`, `clientKey` | Підтвердження картки «було → буде» для дефолту офера | ні |

`clientKey` створюється на клієнті для кожної дії користувача. Повтор з тим самим ключем і вмістом повертає збережений результат, з іншим вмістом — `409 KEY_REUSED`.

Детермінований розпізнавач без Claude обробляє короткі репліки: «запускай», «запусти всі (на сьогодні)», «покажи», «скасуй», «так/ні» на відкрите питання. Вони виконуються як відповідні безкоштовні операції: «запускай» дорівнює `review.show`, а не запуску. Кнопка надсилання для таких реплік показує «Надіслати · 0».

## Від репліки до ефекту

1. **Межі й ціна.** Розмір ≤ 4000 символів. Детермінований розпізнавач. Ціна за `assistant_price_v1`. Debit (контракт [чарунок](credits.md)).
2. **Підготовка контексту.** URL замінюються позначками `⟦url:1⟧`, значення лишаються на сервері. Структурований стан: вибраний офер і країна, набір із картки `contextCardId` (порядкові номери → id). Сервер звіряє автора, простір і версії рядків. Без картки порядкове посилання стає питанням, відкрите питання. Довідники простору — лише назви (офери, баєри, позначки РК), до 200 записів.
3. **Розбір.** Один виклик Claude зі structured output (`output_config.format: json_schema`, той самий механізм, що в 063). JSON Schema генерується з реєстру полів (`assistantPlanSchema`). Відповідь однаково перевіряється на сервері як недовірені дані (`parseAssistantPlan`). Приховані повтори SDK вимкнено (`maxRetries: 0`).
4. **Перевірка плану.** Повна структурна перевірка до першого запису: дії лише з переліку, посилання на кроки лише назад, область кожної вказівки визначена, добуток розгортання ≤ меж.
5. **Зіставлення.** Сирі посилання (`offerRef: "прокапс"`, `materialRefs: ["TR 16"]`, `accountRefs: ["G1".."G5"]`) Soty зіставляє з доступними даними (FR-007). Неоднозначне стає питанням із кнопками, а залежні кроки чекають.
6. **Виконання.** Збереження чернеток через `save_launch_draft` з ключем `op_key:step:row`, правки — з expected version, профіль — пропозицією з маскою, яку застосовує лише `profile.confirm`. Квитанція команди зберігає створені id і попередні версії для скасування.
7. **Відповідь.** Картки будує Soty з перевіреного стану. Текст моделі (коротке пояснення ≤ 300 символів) показується як екранований звичайний текст.

## Дії плану (`plan_launch_actions`)

| Дія | Поля | Примітка |
| --- | --- | --- |
| `create_drafts` | `base` (`offer_defaults` / `copy_of:<rowRef>` / `step:<n>`), `offerRef`, `fields`, `perAccount: accountRefs[]` або `count`, `dates` (`today` / дата / діапазон / `each_day:N`), `overrides: [{scope, fields}]` | Розгортання по РК і датах виконує Soty |
| `update_fields` | `targets` (`rowRef[]` / `all_shown` / `accountRef`), `ops: [{field, op: set/clear/add/remove/reorder, value}]` | Лише поля рівня 1, а також поля рівня 2 з пройденим паритетом |
| `save_offer_defaults` | `offerRef`, `fields` (маска) | Завжди створює картку підтвердження. Профіль змінюється лише після `profile.confirm` |
| `show_review` | `selector` | Без запуску |
| `show_status` | `commandRef` / `batchRef` | |
| `ask` | `about`, `options[]` (≤ 5) | Лише про різницю, що змінює результат |
| `out_of_scope` | — | Коротко перелічити, що помічник уміє |

Запуску генерації в переліку немає (FR-013).

## Реєстр полів (`packages/shared/src/team/launches/fields.ts`)

Кожен запис містить: `key` (шлях у `LaunchConfig`), `tier` (1/2), тип і межі, умову доступності (метод, тип креативу, середовище), чи входить у `LAUNCH_DEFAULT_FIELDS`, допустимі операції, похідні поля, які перераховує Soty, і українські синоніми для системного опису. Із реєстру генеруються:
- JSON Schema для `fields` та `ops`;
- системний опис полів для моделі (кешований префікс);
- тест паритету: для кожного поля створення й правка текстом проти ручного введення дають ту саму збережену чернетку;
- тест інвентарю: редаговані контроли `LaunchEditor` і дочірніх компонентів мають відповідний запис у реєстрі.

Рівень 1: `offerId`, `buyerId`, `agentRowId`, `creatives` (склад, порядок, копії), `campaignCount`, `adsCount`, `budgetMode`, `minBudget`, `maxBudget`, `budgets`, `catalog.productCount`, `originalUrl`, `subConfig.sub1..3`, `launchDate`, `catalog.copyVideoToR2`, `catalog.restitchEnabled`.
Рівень 2: `age`, `gender`, `advantagePlus`, `notes`, кінцева тривалість, `videoVariationCount`, `videoPublication`, `method = other`.

Країна («Туреччина») — підказка для зіставлення матеріалу, бо поля гео в `LaunchConfig` немає. Оперативне призначення РК (`LaunchAssignmentControls`) — окрема дія з власними правами, помічник її не виконує.

## Картки

| Картка | Зміст | Дії |
| --- | --- | --- |
| Результат команди | Дата, кількість рядків/кампаній, матеріали, відмінності від профілю, невирішені поля з причиною, зміна профілю «було → буде» | «Відкрити», «Переглянути й запустити», «Скасувати» |
| Питання | Що саме неоднозначно | Кнопки варіантів |
| Перегляд | Дата, рядки з РК, креативами, кампаніями, бюджетом, R2; неготові з причиною | «Запустити N» |
| Стан | Рядки: прийнято / виконується / готово / помилка (дія відновлення) / невідомо | «Відкрити» |
| Підтвердження профілю | Офер · поле · було → буде | «Зберегти» |
| Відмова | Код причини, локалізований текст | Залежно від причини |

## Коди відповідей

| Умова | HTTP · код |
| --- | --- |
| Непридатний запит або перевищено розмір | 400 `INVALID_INPUT` / 413 `MESSAGE_TOO_LONG` |
| Немає сесії | 401 |
| Немає права на запуски або пілот вимкнено для простору | 403 `ASSISTANT_FORBIDDEN` / `ASSISTANT_DISABLED` |
| Чужий або неіснуючий об'єкт | 404 `NOT_FOUND` (однакове тіло) |
| Ціна змінилась / перегляд застарів / ключ повторно з іншим вмістом / конфлікт правки | 409 `PRICE_CHANGED` / `REVIEW_CHANGED` / `KEY_REUSED` / `EDIT_CONFLICT` |
| Бракує чарунок / вичерпано місяць / частота | 429 `INSUFFICIENT_CREDITS` (+ `resetsAt`) / `AI_MONTH_EXHAUSTED` / `RATE_LIMITED` |
| Старий клієнт | 426 `CLIENT_UPGRADE` |
| Провайдер недоступний / непридатна відповідь моделі | 503 `MODEL_UNAVAILABLE` / 502 `MODEL_OUTPUT_REJECTED` + refund |
| Пакет прийнято | 202 + `batchId` |
