## Перевірено й коректно

- Канонічні імена та URL `Soty-v<v>-macOS-x64.dmg` збігаються в `release.ts`, `release-meta`, `package-mac.sh`/`package-dmg.sh` (`release/x64/`), step-adapter і signer. ARM-шляхи та імена не змінилися.
- Зібраний Dev x64 (`release/dev/x64/Soty Dev.app`): усі 11 Mach-O (launcher, Finder extension, node, ffmpeg, ffprobe, whisper-cli, 5 файлів Chromium) — `x86_64`. Під Rosetta запускаються `node` (v22.23.4, `process.arch=x64`), `ffmpeg`/`ffprobe` 7.1.1 і `whisper-cli --help`. Це не physical Intel acceptance.
- `platformSetVersion` покритий підписом. Веб приймає `undefined` або `2`, і для `2` вимагає всі три закріплені артефакти. Історичний маніфест 1.3.3 валідний у contract і historical режимах.
- Launcher: readiness прив'язана до UUID поточного старту й живого дочірнього процесу. Exact-build orphan і далі обробляється до spawn.
- Мова: нові ключі `macIntel` та `installerUnavailable` є в `uk` і `en`.
- Невідома архітектура: агент повертає `unknown`, веб нормалізує невідомі значення до `unknown`, вибір вимагає явного рішення.

## Відкрите

1. **High (продуктивність, не коректність).** Intel engines зібрано без SIMD:
   - whisper: `GGML_AVX/AVX2/FMA/F16C=OFF`;
   - x264 і FFmpeg: `--disable-asm` / `--disable-x86asm`.

   Транскрипція на Intel буде в рази повільнішою, стиснення — в кілька разів. Рекомендації:
   - Для x264/FFmpeg увімкнути asm. Він має runtime CPU dispatch, тож це безпечно для будь-якого CPU, але потрібен `nasm` на хості збірки.
   - Для whisper увімкнути `GGML_BACKEND_DL=ON` + `GGML_CPU_ALL_VARIANTS=ON` (runtime dispatch). Статичний x86-64-v3 зламав би Mac'и з OCLP до Haswell.

   Не змінено зараз: потрібне перезбирання inputs (важке, ~година) і нова static-кваліфікація.

2. **Apple trust.** Для публікації власник має явно обрати `SOTY_MACOS_TRUST_POLICY=adhoc-pre-048` (як 1.3.3) або налаштувати Developer ID + `MACOS_EXPECTED_TEAM_ID`. Рішення за власником.
3. **Злиття з 047.** Обидві гілки повністю перевизначають `public.analytics_properties_are_safe_v2`, і жодне тіло не містить змін іншої:
   - 047 (`20261207130000`, потім `20261207141000`): `file_surface`, `file_delivery`, `parent_flow_id`, `action='share'`, `storage_kind='unknown'`;
   - 049: `agent_architecture`, `package_target`, `installer_target`, `native_startup_id`.

   Порядок: **спершу 047, потім rebase 049**. Під час rebase тіло `20261207190000` треба перебудувати на базі 047-го `20261207141000_material_link_parent_analytics.sql` і додати чотири ключі 049, їхні словники та UUID-перевірку. `native_startup_id` має бути також у списку opaque-id поруч із `parent_flow_id`. Потім:
   - запустити `tests/analytics-guard-contract.test.ts`: він порівнює останнє тіло з клієнтським allowlist в обидва боки;
   - у pgTAP `analytics-runtime-architecture.test.sql` додати перевірки, що ключі 047 проходять;
   - `events.ts` зливається тривіально, зберегти обидва набори ключів.

   Якщо 047 на момент злиття матиме міграції після `20261207185000`, версію 049 треба підняти вище. Самостійно в 049 об'єднане тіло зробити неможливо: guard-contract тест упав би на зайвих ключах 047.

4. **`deploy:web`** у поточному вигляді вимагає три платформи, тож не передеплоїть канал 1.3.3 до наступного повного релізу. Mini-release (`release:web`) має historical-шлях. Задокументувати або додати historical-варіант, якщо такий деплой знадобиться.
5. **Дрібне:**
   - `beta:verify` на dirty-дереві дає загальний `MACOS_BETA_TARGET_UNPROVEN` замість чіткого повідомлення;
   - `package-beta-mac.sh` тепер відмовляє, якщо beta-застосунок запущений, а не закриває його;
   - тест «every step has an adapter» приймає `GATE_FAILED` для всіх кроків;
   - старі production intents із двома платформами не резолвляться.
6. **T031/T033:** потрібні повні `npm run verify`, `npm run verify:release` і `npm run test:db`, ARM beta native, Windows hosted і Apple trust. Intel runtime — user feedback (T012/T017/T030).
